# API 인가 정책

## 역할

| 역할 | 설명 |
|---|---|
| `ANONYMOUS` | 로그인하지 않은 사용자 |
| `USER` | 활성 상태의 일반 회원 |
| `ADMIN` | 운영 및 관리 권한을 가진 관리자 |

JWT 인증은 DB에 저장된 현재 회원 역할을 `ROLE_USER` 또는 `ROLE_ADMIN` 권한으로 변환한다. 토큰에 역할을 고정하지 않으므로 회원 역할 변경과 계정 비활성화가 다음 요청부터 반영된다.

## 보안 규칙

- `SecurityConfig`는 공개, 로그인 필요, 관리자 전용의 URL 대분류를 한 곳에서 관리한다.
- `@PreAuthorize`는 로그인 회원 ID와 데이터 소유자를 비교하는 세부 인가에 사용한다.
- 체크인·체크아웃, TourAPI 가져오기처럼 업무 의미가 명확한 관리자 동작은 메서드에 `hasRole('ADMIN')`을 선언하고 동일 URL 규칙을 `SecurityConfig`에 중복 선언하지 않는다.
- 클라이언트가 전달한 `memberId`만 신뢰하지 않고 JWT 주체의 회원 ID와 비교한다.
- 리소스 ID로 접근하는 예약, 리뷰, 리뷰 사진, 위시리스트, 인증수단 및 약관동의는 DB 소유자를 확인한다.
- 공개 회원가입 Mapper는 요청의 `role`, `status`, `emailVerified`, `passwordHash` 값을 신뢰하지 않으며 이메일 미인증 상태를 기본값으로 사용한다.
- 회원가입은 Redis에 저장된 이메일 인증 완료 표식을 한 번만 소비한 `AuthService`에서만 이메일 인증 상태를 활성화한다.
- 인증되지 않은 요청은 `401`, 권한 또는 소유권이 없는 요청은 `403`을 반환한다.
- 일반회원의 회원정보 수정은 이름과 전화번호만 허용한다. 역할, 상태, 포인트 및 이메일 인증 상태 변경은 관리자 경로에서만 가능하다.
